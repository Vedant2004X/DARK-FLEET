# DARK-FLEET v0.9 — Read-only analytics and review API

## What this adds

This package adds a read-only API layer over the existing data products:

- historical AIS anomaly outputs stored in `dark_fleet_global_anomaly_index.sqlite3`;
- Phase 3 proximity candidates stored in `phase3_candidates.sqlite3`;
- recent AIS/SAR grid aggregates stored in `recent_grid_local_index.sqlite3`.

It does **not** retrain or overwrite the existing anomaly model, modify candidate scores, create vessel identities from grid aggregates, or write to any existing database. No NumPy, Pandas, scikit-learn, SciPy, or Joblib dependency is required.

## Files

Copy these files into the matching locations:

- `backend/app/v09_analytics.py` → `backend/app/v09_analytics.py`
- `scripts/install_v09_router.ps1` → `scripts/install_v09_router.ps1`
- `scripts/rollback_v09_router.ps1` → `scripts/rollback_v09_router.ps1`
- `backend/tests/test_v09_analytics.py` → `backend/tests/test_v09_analytics.py`

Do not replace `backend/app/main.py`, any existing worker, CSV, or SQLite database.

## Install

From the project root in PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\scripts\install_v09_router.ps1
```

The installer makes a timestamped backup of `backend/app/main.py`, then appends the v0.9 router registration. If registration fails, restore using:

```powershell
.\scripts\rollback_v09_router.ps1
```

No requirements file change is needed.

## Run tests

From the project root, enter the backend folder for the test run:

```powershell
Push-Location backend
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_v09_analytics.py" -v
Pop-Location
```

## Restart the backend

Stop the existing backend terminal with `Ctrl+C`, then run:

```powershell
.\backend\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --app-dir backend
```

Use the same launch command you already use if your current working directory is `backend`.

## Verify endpoints

Open these URLs:

- `http://127.0.0.1:8000/api/v09/status`
- `http://127.0.0.1:8000/api/v09/overview?start_date=2022-01-01&end_date=2022-01-05`
- `http://127.0.0.1:8000/api/v09/review-queue?start_date=2022-01-01&end_date=2022-01-05&limit=10`
- `http://127.0.0.1:8000/api/v09/association-overview`
- `http://127.0.0.1:8000/docs` (search for the v0.9 tag)

For a feature-deviation explanation, first copy an `id` returned by the review queue and open `/api/v09/explain/{id}`.

## Endpoint interpretation

- `status`: confirms which existing artifacts are available and their record coverage.
- `overview`: summarizes the already-saved anomaly outputs over a date range.
- `review-queue`: paginates existing flagged AIS observations by saved score.
- `explain/{observation_id}`: compares speed, speed change, and transmission gap with a vessel-type cohort when at least 30 samples are available; otherwise it uses the full historical cohort.
- `association-overview`: summarizes Phase 3 candidate distance, time-gap, ranking-score and rank distributions.

The explanation is **not SHAP**, does not reconstruct the Isolation Forest's internal decision path, and does not claim causality. Phase 3 candidates remain proximity candidates, not confirmed vessel identities. Recent grid records remain hourly grid-cell/flag aggregates with `identity_available=false`.

## Data protection

The new module opens the existing SQLite files with `mode=ro` and enables `PRAGMA query_only`. It does not rebuild, backfill, rename, delete, or update any existing artifact.
